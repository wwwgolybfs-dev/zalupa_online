# КТО РУИНА? — V4.0

Match ID → OpenDota → анализ с учётом ролей → вердикт.

Один статический сайт без сборки и зависимостей: открывается двойным кликом по `index.html`
и работает на GitHub Pages без настроек.

## Запуск

Локально: открой `index.html` в браузере. Сайт обращается к `api.opendota.com` напрямую,
CORS это разрешает.

Через локальный сервер (если браузер ограничивает запросы с `file://`):

```bash
python -m http.server 8000
# затем http://localhost:8000
```

На GitHub Pages: `Settings → Pages → Deploy from a branch → main / (root)`. После публикации
подставь в `index.html` абсолютные адреса `og:url` и `og:image`, иначе превью в Telegram
может не подтянуться.

## Как считается вердикт

1. Матч тянется из OpenDota, определяется проигравшая команда.
2. Роли POS 1–5: `lane_role` (1 = safe, 2 = mid, 3 = offlane), внутри линии игроки делятся
   по ресурсам; если данных по линиям нет, позиции добираются по net worth/GPM/last hits/XPM.
3. Каждый игрок получает blame-оценку с весами по роли: фарм, вклад в драки, цена смертей,
   давление на объекты, полезность (вижен/лечение). Отдельно ловится «богатый, но бесполезный»
   сценарий: высокий GPM при низком уроне и слабом давлении на строения.
4. Надёжность вывода зависит от полноты данных. Если матч не разобран — это видно в интерфейсе.

## Ограничения

- Пороги модели (`expectedGpm`, `expectedKP`, доля урона, урон по строениям) подобраны вручную,
  не зависят от ранга и длительности матча и не калибровались на выборке. Это следующий шаг:
  сравнение с визави по линии и нормализация по рангу.
- OpenDota без API-ключа ограничивает частоту запросов (примерно 60 в минуту и 2000 в сутки
  на IP). Кеш справочников снижает расход, но при активном использовании лимит всё равно
  достижим. Если понадобится — можно добавить ключ через маленький прокси.
- Оценка — эвристика для разбора, а не приговор игроку: сервис показывает сигналы и контекст,
  а не «виновного».
