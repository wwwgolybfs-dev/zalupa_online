# КТО РУИНА? — V4.2

Match ID → OpenDota → анализ с учётом ролей → вердикт.

Один статический сайт без сборки и зависимостей: открывается двойным кликом по `index.html`
и работает на GitHub Pages без настроек.

## Что нового в V4.2

- **Картинки живут в репозитории.** Все изображения героев (127), предметов (501 id → 417
  файлов, рецепты делят одну картинку) и иконки рангов (8) скачаны в `assets/` и раздаются
  локально — сайт больше не ходит на Steam CDN и не грузит справочники с OpenDota.
- **Справочники — статические `.js`** (`data/heroes.js`, `data/items.js`, `data/ranks.js`):
  соответствие id → имя и локальный путь. Загружаются через `<script>`, поэтому работают и с
  `file://` (обычный `fetch` JSON из локального файла браузер бы заблокировал).
- **Скрипт обновления ассетов** `tools/fetch-assets.py` (только стандартная библиотека Python):
  перекачивает картинки и перегенерирует `data/*.js`. Достаточно запустить, когда выйдут новые
  герои/предметы, и закоммитить изменения.
- Из `js/app.js` убран фетч констант и весь код кеширования справочников — сайт стал проще и
  на 2 запроса к OpenDota легче на каждый разбор.

## Обновление картинок героев/предметов

```bash
python tools/fetch-assets.py          # докачать недостающее
python tools/fetch-assets.py --force  # перекачать всё
```

Источники: справочники `github.com/odota/dotaconstants`, картинки — Steam CDN, ранги —
зеркало `github.com/odota/ui`. После запуска закоммить `assets/` и `data/`.

## Запуск

Локально: открой `index.html` в браузере. Сайт обращается к `api.opendota.com` напрямую,
CORS это разрешает.

Через локальный сервер (если браузер ограничивает запросы с `file://`):

```bash
python -m http.server 8000
# затем http://localhost:8000
```

На GitHub Pages: `Settings → Pages → Deploy from a branch → main / (root)`. После публикации
подставь в `index.html` абсолютные адреса `og:url` и `og:image`, иначе превью в Telegram
может не подтянуться.

## Как считается вердикт

1. Матч тянется из OpenDota, определяется проигравшая команда.
2. Роли POS 1–5: `lane_role` (1 = safe, 2 = mid, 3 = offlane), внутри линии игроки делятся
   по ресурсам; если данных по линиям нет, позиции добираются по net worth/GPM/last hits/XPM.
3. Каждый игрок получает blame-оценку с весами по роли: фарм, вклад в драки, цена смертей,
   давление на объекты, полезность (вижен/лечение). Отдельно ловится «богатый, но бесполезный»
   сценарий: высокий GPM при низком уроне и слабом давлении на строения.
4. Надёжность вывода зависит от полноты данных. Если матч не разобран — это видно в интерфейсе.

## Мост к OpenDota (ускорение загрузки)

Прямой путь «домашний канал → OpenDota» медленный на крупных ответах, а Cloudflare-воркеры
выходят с общих IP, на которых у OpenDota выбран суточный лимит. Поэтому в проекте два
прокси-моста, которые заодно кешируют ответы:

```
браузер → Supabase Edge Function → Cloudflare Worker → OpenDota (напрямую)
                 (Нидерланды)            (кеш на час)
```

В `js/app.js` задаются адреса мостов; приоритет — сверху вниз, при недоступности
происходит откат к следующему уровню, а последний уровень — прямой запрос.
Если обе константы пустые, сайт работает напрямую, как раньше.

- Cloudflare-воркер: `bridge/` (задеплоен, кеш через Cache API).
- Supabase Edge Function: `supabase/` (требуется деплой в твой проект).

Ключ OpenDota (если он есть) хранится **на стороне моста** и в браузер не попадает:
у Cloudflare это секрет `OPENDOTA_KEY`, у Supabase — `supabase secrets set OPENDOTA_KEY=...`.

## Ограничения

- Пороги модели (`expectedGpm`, `expectedKP`, доля урона, урон по строениям) подобраны вручную,
  не зависят от ранга и длительности матча и не калибровались на выборке. Это следующий шаг:
  сравнение с визави по линии и нормализация по рангу.
- OpenDota без API-ключа ограничивает частоту запросов (примерно 60 в минуту и 2000 в сутки
  на IP). Кеш справочников снижает расход, но при активном использовании лимит всё равно
  достижим. Если понадобится — можно добавить ключ через маленький прокси.
- Оценка — эвристика для разбора, а не приговор игроку: сервис показывает сигналы и контекст,
  а не «виновного».
